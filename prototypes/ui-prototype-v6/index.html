The prompt you are testing. The tool uses it exactly as written and adds nothing to it. Help

How to use Judge the Judge.

What does this tool do?

It tests an LLM-as-judge prompt. You write scenarios (input fields plus the errors the judge should find), run the final prompts in your LLM, paste what you receive, and decide Pass or Fail for each scenario. The tool counts, compares and reports.

The whole flow
  1. Paste your judge prompt (the tool never changes it). Mark where each scenario field goes with placeholders such as {{input}}.
  2. Fill the error catalog (or press Populate for accuracy / completeness), load or write scenarios, then finalize the dataset.
  3. For each scenario copy the final prompt, run it in your LLM and paste the output.
  4. Results: clear outputs get an automatic verdict; you verify the rest (optionally with a second opinion from your LLM). The tool then gives a final answer: Works, Does not work or Inconclusive.
  5. Save the result to JSON or export an HTML report. To try another prompt, use “Change the judge, keep the cases”, then compare.
Scenarios, fields and expected errors

A scenario has a name and any number of named input fields, for example prompt_under_review and input. Your judge prompt refers to them with placeholders like {{input}}. Each expected error has a description and optionally a field, a label and a fragment. No expected errors means a clean scenario. After finalizing, inputs stay fixed but you can still adjust the expected errors.

Error catalog

The error catalog is one list of the kinds of errors your judge looks for, one per line, optionally with a description after a dash. Type it, paste it, load it from a JSON file ({"name":"Tone","labels":[{"name":"too-formal","description":"…"}]}) or press Populate for accuracy / Populate for completeness, which writes a ready judge prompt and the matching list. The list feeds the label choices for expected errors and the prompt that asks your LLM to generate test data.

Writing errors in one line

Format: field | label | "fragment" | description. Shorter forms work too: label | description or just a description. In CSV put several errors in one cell separated by ;; . CSV columns: id (optional), name, one field:<name> column per input field (or a single text column), and expected_errors.

Generating test data with your LLM

Each scenario card has a “Prompt for generating test data”. It contains your judge prompt, the labels with their definitions and the base scenario. Run it in your LLM and paste the answer in “Paste scenarios from your LLM”: it is read like a file and you review every scenario before it is added. No prompt guarantees an exact result.

Verification and measures

An expected error is found when the judge reports the same label and its quote overlaps the expected fragment (the label alone counts when the expected error has no fragment). The detection rate is expected errors found divided by all expected errors. An unexpected finding is something the judge reports that was not expected; the false-alarm rate is the share of scenarios (clean or not) with at least one. A scenario passes only when every expected error is found and nothing unexpected is reported. Intervals are 95%. Results are provisional while scenarios await verification.

Final answer and thresholds

Works: detection at least 80% and false alarms at most 10% (both editable on the Results step). Does not work: either threshold missed. Inconclusive: scenarios are not run or still await verification, or the sample is below the minimum (30 expected errors and 10 clean scenarios by default). The values used are stored with the result and printed in the report.

Second opinion from an LLM

On the Results step, copy the verification prompt for the scenarios that await verification, run it in your own LLM and paste the JSON answer back. It only fills in the marks as a proposal; nothing counts until you approve it, and the report shows the source of every verdict.

Saving your work

The tool remembers nothing after you close the page. Save scenarios to JSON, results to JSON, or export an HTML report. You are warned before leaving with unsaved work. Saved results and reports always contain your full prompts, input data and received outputs, so handle those files like the data itself.
